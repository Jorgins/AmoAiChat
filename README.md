# AmoAiChat

Чат с нейропомощником для AmoCRM: ИИ-консультант «Николай» сам отвечает клиенту
по базе знаний, а менеджер видит подсказки по допродажам и может вступить в
диалог в любой момент. Демо-интерфейс выполнен в стиле диалогового окна AmoCRM.

Простой сервис: принимает сообщение клиента (+ опционально историю переписки
из диалогового окна AmoCRM), сверяется с короткой базой знаний и возвращает
два блока:

1. **reply_to_client** — готовый вежливый ответ клиенту.
2. **upsell_hint** — подсказка менеджеру по возможной допродаже, основанная
   на теме обращения и ходе диалога.

Интеграции с AmoCRM (вебхуки, OAuth) в этой версии нет — сервис принимает
обычный JSON. Он рассчитан на то, чтобы его дальше можно было дёрнуть из
вебхука AmoCRM при поступлении нового сообщения в чат.

## Установка

```bash
pip install -r requirements.txt
copy .env.example .env   # затем впишите свои значения (по умолчанию — Z.ai/GLM)
```

`.env` содержит секретный ключ — он уже в `.gitignore`, не коммитьте его.

## Запуск

```bash
python app.py
```

Сервис поднимется на `http://localhost:8000`. Документация Swagger — на
`http://localhost:8000/docs`.

## Проверка

Вариант 1 (рекомендуется) — веб-интерфейс в стиле диалогового окна AmoCRM:
откройте `http://localhost:8000/` в браузере. Слева — окно переписки (можно
писать «от имени клиента»), справа — панель ИИ-помощника: черновик ответа
клиенту (с кнопкой «Отправить клиенту в чат») и отдельная карточка с
подсказкой по допродаже для менеджера, которая клиенту не отправляется.

Вариант 2 — интерактивный CLI в консоли, имитирующий переписку в AmoCRM:

```bash
python test_client.py
```

Вариант 3 — напрямую через curl (на Windows с кириллицей в аргументах curl
могут быть проблемы с кодировкой — надёжнее использовать веб-интерфейс,
`test_client.py` или Swagger UI на `/docs`). Пример из демо-базы знаний
(продажа дизель-генераторов):

Первое сообщение — расплывчатый запрос, модель должна не гадать модель, а
задать уточняющие вопросы:

```bash
curl -X POST http://localhost:8000/process-message ^
  -H "Content-Type: application/json" ^
  -d "{\"client_message\": \"Здравствуйте! Какой дизель генератор мне приобрести для моих задач?\"}"
```

Ответ (пример):

```json
{
  "reply_to_client": "Здравствуйте! Чтобы подобрать подходящий генератор, уточните, пожалуйста: для каких целей он нужен — резервное питание или основной источник? Какая примерно суммарная мощность потребителей? Нужен однофазный (220В) или трёхфазный (380В)? Важен ли автозапуск при отключении электричества?",
  "upsell_hint": "Клиент ещё не определился с параметрами — продолжайте диалог. Как только он назовёт мощность/задачи, держите в голове допродажу: моторное масло для первого ТО и силовой кабель/удлинитель для подключения."
}
```

Второе сообщение (клиент назвал параметры) — теперь можно передать историю
диалога, чтобы модель учла контекст и подсказала менеджеру конкретный апсейл:

```bash
curl -X POST http://localhost:8000/process-message ^
  -H "Content-Type: application/json" ^
  -d "{\"client_message\": \"Нужен для дачи, на 8-10 кВт, однофазный, с автозапуском\", \"dialog_history\": [{\"role\": \"client\", \"text\": \"Какой дизель генератор мне приобрести для моих задач?\"}, {\"role\": \"manager\", \"text\": \"Уточните, пожалуйста, мощность и нужен ли автозапуск\"}]}"
```

Ответ (пример):

```json
{
  "reply_to_client": "Спасибо! Под ваши параметры (8-10 кВт, 220В, с АВР) менеджер подберёт конкретную модель и свяжется с вами для подтверждения.",
  "upsell_hint": "Клиент определился с параметрами — предложите моторное масло для первого ТО и силовой кабель/удлинитель для подключения к щитку. Также, раз нужен автозапуск — можно предложить платный монтаж и пуско-наладку."
}
```

## Структура

- `knowledge_base.json` — короткая база знаний (тематики, уточняющие вопросы,
  каталог моделей генераторов с ценами, подсказки по допродаже +
  upsell_playbook). Каталог моделей — реальные позиции с публичного каталога
  vseinstrumenti.ru на момент сборки, для демонстрации. **Замените на свои
  актуальные данные** перед использованием в проде.
- `app.py` — FastAPI-сервис: `POST /process-message`, `GET /health`, и отдаёт
  веб-интерфейс на `GET /`.
- `static/index.html` — веб-интерфейс в стиле диалогового окна AmoCRM (один
  файл, без сборки).
- `test_client.py` — CLI для ручной проверки без браузера.

## Как это подключить к AmoCRM

Сейчас сервис — независимый HTTP-эндпоинт. Чтобы менеджер получал ответ и
подсказку прямо в карточке сделки, нужен отдельный шаг интеграции:

1. Настроить в AmoCRM исходящий вебхук на событие "новое сообщение в чате".
2. Обработчик вебхука вызывает `POST /process-message` с текстом сообщения
   и историей переписки (её можно получить через AmoCRM API по `chat_id`).
3. `reply_to_client` можно отправить клиенту автоматически или показать
   менеджеру как черновик; `upsell_hint` — добавить как примечание к сделке
   или показать в виджете рядом с чатом (в чат клиенту не отправлять).

Этот шаг не реализован намеренно — требует ключей доступа к конкретному
аккаунту AmoCRM.

## Настройка модели / провайдера

По умолчанию сервис использует библиотеку `anthropic`, но настроен (через
`ANTHROPIC_BASE_URL`/`ANTHROPIC_AUTH_TOKEN` в `.env`) на Z.ai (модели GLM) —
это Anthropic-совместимый прокси, поэтому код не завязан на конкретного
провайдера. Модель задаётся через `CLAUDE_MODEL` в `.env` (сейчас `glm-5.2`).

Чтобы перейти на настоящий Claude API — уберите `ANTHROPIC_BASE_URL` и
`ANTHROPIC_AUTH_TOKEN`, укажите `ANTHROPIC_API_KEY` и `CLAUDE_MODEL=claude-opus-5-5`
(или `claude-sonnet-5-5` для более дешёвых высоконагруженных сценариев).
